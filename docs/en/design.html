Design

conv-docs (Convenient Documents) is an independent read-only document gateway: it serves explicitly published workspace directories from your PC, through a dedicated hostname on your Cloudflare Tunnel, to a mobile reader protected by a token. This page is the implementation blueprint and the security model.

1. Goals and non-goals

Goals

① Visible only after an explicit publish (R1) ② strictly read-only (R2) ③ Markdown / HTML rendering (R3) ④ token auth (R4) ⑤ fully isolated from the herdr-remote control plane (R5)

Non-goals

No editing, no multi-user/permission system, no full-text search, no replacement for herdr-remote's agent control, nothing hosted in the cloud

2. Architecture

Phone browser / PWA │ HTTPS ▼ docs.yourdomain ──── Cloudflare Tunnel (same tunnel as relay, separate ingress rule) │ ▼ conv-docs service (127.0.0.1:8380, Python standard library) ├─ Auth Bearer token (hash storage + constant-time compare + failure rate limiting) ├─ Grants publish list (explicit publish / unpublish) ├─ Files path sandbox (realpath containment, symlink-escape refusal, hidden files skipped, │ extension allowlist) └─ Rendering in the browser: marked + DOMPurify + highlight.js (vendored) │ ▼ published workspace directories (loopback only; exposed solely via the tunnel) herdr-remote relay :8375 ── control plane, untouched

Key decision: the document service is physically isolated from the agent control plane — different port, different hostname, different token. The document service parses untrusted file content; keeping it in a separate, minimal-privilege process means a parsing bug cannot reach the WebSocket interface that issues commands to agents. That is how "without hurting daily use" is implemented: the existing relay needs zero changes.

3. Core concepts

ConceptDefinition
Published rootA name → absolute directory mapping added explicitly with conv-docs publish and removed with conv-docs unpublish, persisted in the config file. There are no roots by default — a fresh install exposes nothing.
TokenA 256-bit random value; the server stores only its SHA-256 hash (config file 0600). The phone enters it once and keeps it in the browser. conv-docs token rotate revokes and replaces it instantly.
Path sandboxEvery file access resolves the relative path to a realpath and verifies it still lies inside a published root; any escape (../, absolute paths, symlinks pointing outside) is refused.
One-shot ticketFor HTML full mode: an authenticated call exchanges a 30-second, single-use ticket bound to one file, so the long-lived token never appears in a URL.

4. Command line

$ uv run conv-docs publish ~/work/proj-a --as proj-a   # explicit publish
$ uv run conv-docs list                                  # show the publish list
$ uv run conv-docs unpublish proj-a                      # revoke
$ uv run conv-docs token rotate                          # new token (printed once)
$ uv run conv-docs serve --host 127.0.0.1 --port 8380    # start the service

(uv run conv-docs is equivalent to python3 -m conv_docs if you don't use uv.) Config file ~/.config/conv-docs/config.json (mode 0600); audit log ~/.local/state/conv-docs/audit.log (JSONL). Publishing changes take effect immediately — the service hot-reloads the config file.

5. HTTP API (/api/v1)

Everything except health requires Authorization: Bearer <token>. One exception: rawhtml is loaded as a browser iframe navigation, which cannot carry headers — there the one-shot ticket is the credential (and only an authenticated caller can obtain one). Only GET/HEAD are accepted; all other methods return 405 (WebDAV verbs explicitly rejected).

EndpointReturnsNotes
GET /api/v1/healthJSONUnauthenticated liveness; only {ok, service, version}
GET /api/v1/rootsJSONPublished roots (name, real path, entry count)
GET /api/v1/tree?root=&path=JSONDirectory listing: name, kind (dir/text/image/…), size, mtime. Hidden and unsupported entries never appear
GET /api/v1/meta?root=&path=JSONSingle-file metadata (kind, size, mtime)
GET /api/v1/raw?root=&path=raw bytesFile content. Text is always returned as text/plain, images as image/*, PDF as application/pdf. User content is never served as text/html — rendering happens only after client-side sanitisation
GET /api/v1/html-ticket?root=&path=JSONIssues a one-shot ticket (30 s) for HTML full mode
GET /api/v1/rawhtml?root=&path=&ticket=text/htmlThe only endpoint that returns HTML, guarded by the one-shot ticket. The response forces Content-Security-Policy: sandbox … (without allow-same-origin), giving the document an opaque origin: its scripts may run, but they cannot reach the viewer's token, localStorage or DOM

Every response carries X-Content-Type-Options: nosniff; API responses also carry Cache-Control: no-store. No CORS headers are set, so pages on other origins cannot read responses.

6. Rendering pipeline

TypePipeline
Markdown (.md/.markdown)marked → DOMPurify sanitise → inject → highlight.js for code blocks. Relative in-page links are rewritten to viewer routes, external links get rel="noopener noreferrer"; relative images are fetched through the authenticated API and shown as blob URLs
HTML (.html/.htm), default modeDOMPurify whole-document sanitisation (styles and structure kept, scripts and event handlers stripped); the document's own relative stylesheets are fetched and inlined. Covers the vast majority of reading
HTML full mode (opt-in per file)One-shot ticket → sandboxed iframe loading rawhtml. Document scripts run (interactive charts etc.) inside an opaque-origin sandbox that cannot touch the token or page data
Plain text / codehighlight.js display (the text/plain original is never executed)
Images / PDFShown via blob URLs; SVG renders as an image (scripts do not run in <img> context)

7. Security model (threat → countermeasure)

ThreatCountermeasure
Strangers reading documents (R4)Bearer token required; server stores a hash with constant-time comparison; failed auth is rate-limited per source (10 failures / 15 min → temporary block); token rotate revokes instantly
Tunnel used to read unauthorised directories (R1)No roots by default; the publish list is persisted and instantly revocable; every request re-checks realpath containment; symlinks escaping the root are refused; hidden files/dirs (.git, .env, …) are skipped; files outside the extension allowlist are unavailable
Malicious document scripts stealing the token or impersonating the UIThe server never serves user content as text/html (text/plain + nosniff before rendering); the client sanitises with DOMPurify; full mode runs in a CSP sandbox without allow-same-origin; the viewer itself ships a strict CSP (default-src 'none'; script-src 'self'; frame-src 'self' blob:; base-uri 'none'; form-action 'none')
Any write attempt (R2)No write endpoint exists; the method allowlist is GET/HEAD and WebDAV verbs return 405; request bodies are never consumed
Token leaking into logs/URLsThe token travels only in the Authorization header; tickets are short-lived, single-use and file-bound; the audit log records events and paths, never credentials
Repudiation / after-the-fact reviewJSONL audit log: failed auth, ticket rejections, file access (time, source IP, root, path)
Resource exhaustion (huge files)Render size cap (default 2 MB, with an explicit "render anyway" option); per-connection timeouts; oversized URLs and request bodies refused
Bleeding into the agent control plane (R5)Separate process, port, hostname and token; loopback binding, exposed only through the tunnel; herdr-remote relay untouched

Residual risks, stated plainly: ① non-hidden sensitive files inside a published directory (a hand-written password in notes.yaml) are readable by the token holder — check what you publish, or use --docs-only; ② full-mode document scripts can still make network requests (the sandbox blocks same-origin access only) — use the default mode for untrusted HTML; ③ a token leaked from the phone equals the whole document set — call token rotate immediately.

8. Acceptance criteria

RequirementHow it is verified
R1 Explicit grantTests: unpublished paths are invisible in tree/roots and return 404; unpublish takes effect immediately
R2 Read-onlyTests: POST/PUT/DELETE/MKCOL/PROPFIND … all 405; no write endpoint exists
R3 RenderingTests + real-browser checks: md renders with highlighted code, HTML sanitises correctly, full-mode sandbox verified
R4 TokenTests: no token 401, wrong token 401, repeated failures 429; real phone login verified
R5 Safe and unobtrusiveTests assert response headers (nosniff/CSP); herdr-remote config unchanged (one ingress rule added)
