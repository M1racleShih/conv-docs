Deployment & Usage

From zero to reading on your phone: install the service, generate a token, publish directories, join your Cloudflare Tunnel, and daily operations.

1. Requirements

  • Python 3.10+ (the server has zero third-party runtime dependencies)
  • uv (recommended): project environment and dependency locking; without uv, plain python3 -m conv_docs works too
  • Node.js (optional, only to rebuild the TypeScript viewer; the compiled app.js is committed)
  • cloudflared (the Cloudflare Tunnel you already use for herdr-remote is fine)
  • systemd (optional, for running as a service)

2. Install and first start

git clone <this repo> conv-docs && cd conv-docs

# 0. Prepare the environment (uv; equivalent: python3 -m conv_docs …)
uv sync

# 1. Generate the access token (printed once — save it for your phone)
uv run conv-docs token rotate

# 2. Explicitly publish a workspace directory (nothing is exposed by default)
uv run conv-docs publish ~/work/proj-a --as proj-a

# 3. Start (listens on 127.0.0.1:8380 only)
uv run conv-docs serve

Verify from the PC browser at http://127.0.0.1:8380: after entering the token you should see the published directory.

Run as a service (systemd user unit)

bash scripts/install-service.sh

The script writes ~/.config/systemd/user/conv-docs.service, enables and starts it, and prints a cloudflared ingress snippet. If no token exists yet it generates one. Management:

systemctl --user status conv-docs
systemctl --user restart conv-docs
journalctl --user -u conv-docs -f

3. Join your Cloudflare Tunnel

conv-docs shares the tunnel with herdr-remote without interfering: you add one hostname mapping to the ingress rules; the relay's rules and token stay exactly as they are.

# ~/.cloudflared/config.yml (sketch — keep your existing rules)
ingress:
  - hostname: relay.yourdomain.example   # existing herdr-remote rule, unchanged
    service: http://127.0.0.1:8375
  - hostname: docs.yourdomain.example    # new: the docs gateway
    service: http://127.0.0.1:8380
  - service: http_status:404             # catch-all must stay last
cloudflared tunnel route dns <tunnel-name> docs.yourdomain.example
cloudflared tunnel ingress validate
systemctl --user restart cloudflared     # or your cloudflared run mode

Verify: open https://docs.yourdomain.example/api/v1/health from the phone and the PC — you should get {"ok": true, ...}. Requesting /api/v1/roots without a token must return 401.

4. On the phone

  1. Open https://docs.yourdomain.example, paste the token (it stays in the browser's local storage).
  2. "Workspaces" lists published directories → tap through the tree → tap a file to read it rendered. Markdown renders directly; HTML uses safe render (scripts stripped) by default — switch to "Full mode" for interactive content.
  3. Use "Add to Home Screen" to treat it as an app. The UI defaults to English and switches to Chinese with one tap; it follows the system light/dark theme and can be pinned in the header.

5. Daily operations

GoalCommand / action
Publish another workspaceuv run conv-docs publish <dir> --as <name> — effective immediately, no restart
Revoke a workspaceuv run conv-docs unpublish <name> — effective immediately
Show the publish listuv run conv-docs list
Rotate the token (leak or routine)uv run conv-docs token rotate — old token dies at once; also saved to ~/.config/conv-docs/token.txt (0600)
Docs and images onlypublish with --docs-only (code and data files stay hidden)
Review accesstail -f ~/.local/state/conv-docs/audit.log (JSONL: failed auth, publish changes, file access)
Config file~/.config/conv-docs/config.json (0600, token hash only, never plaintext)

6. Security checklist

  • The service binds 127.0.0.1 only and is exposed through the tunnel; never use --host 0.0.0.0.
  • Use the random token from token rotate, not a chosen password; the device holding the token is a trusted device.
  • Before publishing, confirm the directory contains nothing you would not want on your phone; when unsure, add --docs-only.
  • Hidden files/dirs (.git, .env, …) are never served; files outside the extension allowlist are never served.
  • Optional second layer: put a Cloudflare Access policy (e.g. email OTP) in front of docs.* and keep the token as the application-level credential.

7. Troubleshooting

SymptomCheck
401 on the phoneIs the token complete? Was it rotated? 10 consecutive failures trigger a 15-minute block (wait or switch network)
404 for a directory/fileconv-docs list — is it published? Is the file hidden or outside the extension allowlist? Path spelling
502/530 through the tunnelsystemctl --user status conv-docs; cloudflared tunnel ingress validate; is the docs rule above the catch-all?
HTML full mode is blankThe ticket is single-use and lasts 30 seconds — tap "Full mode" again; scripts constrained by the sandbox are expected behaviour
Styles missingExternal <link> stylesheets are blocked by CSP by design; relative stylesheets are inlined automatically
