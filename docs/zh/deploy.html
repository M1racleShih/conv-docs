部署与使用手册

从零到手机可读：安装服务、生成 token、发布目录、接入 Cloudflare Tunnel、手机端使用与日常运维。

一、依赖

  • Python 3.10+（服务端零第三方运行时依赖，只用标准库）
  • uv（推荐）：管理项目环境与依赖锁定，uv sync 一键就绪；没有 uv 直接用 python3 -m conv_docs 也可以
  • cloudflared（接入你已有的 Cloudflare Tunnel 即可）
  • systemd（可选，用于常驻；不用 systemd 也能直接前台运行）

二、安装与首次启动

git clone <本仓库> conv-docs && cd conv-docs

# 0. 准备环境（uv；等价做法：python3 -m conv_docs ...）
uv sync

# 1. 生成访问 token（明文只显示一次，保存到手机）
uv run conv-docs token rotate

# 2. 显式发布一个 workspace 目录（默认什么都不暴露）
uv run conv-docs publish ~/work/proj-a --as proj-a

# 3. 启动（默认只监听 127.0.0.1:8380）
uv run conv-docs serve

本机浏览器打开 http://127.0.0.1:8380 验证：输入 token 后应能看到已发布的目录。

常驻运行（systemd 用户服务）

bash scripts/install-service.sh

脚本会写入 ~/.config/systemd/user/conv-docs.service、设置开机自启并启动服务；没有 token 时会先生成一个并打印。管理命令：

systemctl --user status conv-docs
systemctl --user restart conv-docs
journalctl --user -u conv-docs -f

三、接入 Cloudflare Tunnel

conv-docs 与已有服务共用隧道但互不干扰：只是在 ingress 规则里新增一条 hostname 映射，已有规则与 token 一个字都不用改。

# ~/.cloudflared/config.yml（示意，保持你已有的规则）
ingress:
  - hostname: relay.你的域名        # 已有的规则，原样保留
    service: http://127.0.0.1:8375
  - hostname: docs.你的域名         # 新增：文档网关
    service: http://127.0.0.1:8380
  - service: http_status:404        # catch-all 必须在最后
cloudflared tunnel route dns <你的隧道名> docs.你的域名
cloudflared tunnel ingress validate
systemctl --user restart cloudflared   # 或你现有的 cloudflared 运行方式

验证：手机与 PC 都访问 https://docs.你的域名/api/v1/health，返回 {"ok": true, ...} 即隧道通了。不带 token 访问 /api/v1/roots 必须返回 401。

四、手机端使用

  1. 浏览器打开 https://docs.你的域名，粘贴 token 进入（token 只存在手机浏览器本地）。
  2. 「工作区」列出已发布的目录 → 点进目录浏览 → 点文件即渲染阅读。Markdown 直接渲染；HTML 默认是安全渲染（脚本被清洗），需要交互式内容时切「完整模式」。
  3. 建议「添加到主屏幕」当作 App 使用；界面默认英文，顶栏一键切换中文；跟随系统深浅色，也可在顶栏固定。

五、日常运维

想做什么命令 / 操作
新增一个 workspaceuv run conv-docs publish <目录> --as <名字>，即时生效，无需重启
撤销某个 workspaceuv run conv-docs unpublish <名字>，即时生效
查看发布清单uv run conv-docs list
token 泄漏 / 定期轮换uv run conv-docs token rotate（旧 token 立即失效；新 token 同时自动保存到 ~/.config/conv-docs/token.txt（0600），手机重新输入即可）
只放行文档与图片发布时加 --docs-only（代码、数据文件一律不出现在列表）
查看访问审计tail -f ~/.local/state/conv-docs/audit.log（JSONL：认证失败、发布变更、文件访问）
配置文件~/.config/conv-docs/config.json（0600，只存 token 哈希，不存明文）

六、安全清单（部署时过一遍）

  • 服务只绑定 127.0.0.1，只经隧道暴露；不要用 --host 0.0.0.0。
  • token 用 token rotate 生成的随机值，不要自拟弱口令；手机端保存 token 的设备视为受信设备。
  • 发布前确认目录里没有不想给手机看的非隐藏敏感文件；拿不准就加 --docs-only。
  • 隐藏文件/目录（.git、.env 等）永远不会被服务，扩展名白名单之外的文件也不会。
  • 可选第二层：在 Cloudflare Zero Trust 里给 docs.你的域名 配 Access 策略（如邮箱 OTP），token 只作为应用层凭证。

七、故障排查

现象排查
手机 401token 是否输入完整；是否已 rotate 过；连续失败 10 次会封禁 15 分钟（换网络或等待）
手机 404（目录/文件）conv-docs list 确认已发布；文件是否隐藏/不在扩展名白名单；路径拼写
隧道 502/530systemctl --user status conv-docs；cloudflared tunnel ingress validate；ingress 里 docs 规则是否在 catch-all 之前
HTML 完整模式空白ticket 只有 30 秒且一次性，重新点「完整模式」；文档脚本被沙箱约束属预期
页面样式丢失文档的 <link> 外站样式被 CSP 拦截属预期；站内相对样式会自动内联
