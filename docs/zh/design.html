方案设计

conv-docs 是一个独立的只读文档网关：把 PC 上显式发布的 workspace 目录，通过 Cloudflare Tunnel 上的独立子域名，以 token 认证的方式提供给手机端渲染阅读。本页是实现蓝图与安全模型。

一、目标与非目标

目标

① 显式发布才可见（R1）② 纯只读（R2）③ Markdown / HTML 渲染（R3）④ token 认证（R4）⑤ 与 herdr-remote 控制通道完全隔离（R5）

非目标

不做编辑、不做多用户/权限体系、不做全库搜索、不替代 herdr-remote 的 agent 控制功能、不托管到云端

二、总体架构

手机浏览器 / PWA │ HTTPS ▼ docs.你的域名 ──── Cloudflare Tunnel（与 relay 同一隧道，独立 ingress 规则） │ ▼ conv-docs 服务（127.0.0.1:8380，Python 标准库） ├─ 认证层 Bearer token（哈希存储 + 常数时间比较 + 失败限速） ├─ 授权层 发布清单（publish / unpublish 显式管理） ├─ 文件层 路径沙箱（realpath 包含性检查、符号链接逃逸拒绝、隐藏文件跳过、扩展名白名单） └─ 渲染层 浏览器端：marked + DOMPurify + highlight.js（本地 vendor） │ ▼ 已发布的 workspace 目录（默认只绑定 127.0.0.1，不直连公网） herdr-remote relay :8375 ── 控制通道，完全不动

关键决策：文档服务与 agent 控制通道物理隔离——不同的端口、不同的子域名、不同的 token。文档服务解析的是不可信文件内容；把它放在攻击面最小的独立进程里，解析层就算出问题，攻击者也触及不到向 agent 发指令的 WebSocket 接口。这就是「不影响我使用」的实现方式：现有 relay 零改动。

三、核心概念

概念定义
发布根（root）一条 名字 → 绝对目录 的映射，由 conv-docs publish 显式添加、conv-docs unpublish 撤销，持久化在配置文件里。默认没有任何发布根——刚装完的 conv-docs 看不到任何文件。
token256 位随机值，服务端只保存它的 SHA-256 哈希（配置文件 0600）。手机端输入一次保存在浏览器本地。支持 conv-docs token rotate 一键吊销旧 token。
路径沙箱所有文件访问先把相对路径解析为 realpath，再验证其仍位于某个发布根之内；任何逃逸（../、绝对路径、指向外部的符号链接）都拒绝。
一次性 ticketHTML 完整模式专用：换取一个 30 秒有效、单次使用的 ticket，再带 ticket 打开沙箱页面。避免把长期 token 放进 URL。

四、命令行接口

$ uv run conv-docs publish ~/work/proj-a --as proj-a   # 显式发布
$ uv run conv-docs list                                  # 查看发布清单
$ uv run conv-docs unpublish proj-a                      # 撤销
$ uv run conv-docs token rotate                          # 生成/轮换 token（明文只显示一次）
$ uv run conv-docs serve --host 127.0.0.1 --port 8380    # 启动服务

配置文件 ~/.config/conv-docs/config.json（权限 0600），审计日志 ~/.local/state/conv-docs/audit.log（JSONL）。发布清单热加载：publish / unpublish 即时生效；token rotate 会把新 token 顺带写入同目录 token.txt（0600）。移动端查看器用 TypeScript 编写（web-src/app.ts，编译产物已提交），界面默认英文、内置中文切换。

五、HTTP API（/api/v1）

除 health 外全部要求 Authorization: Bearer <token>；唯一例外是 rawhtml——它是浏览器 iframe 导航，无法携带请求头，改以一次性 ticket 作为该端点的凭证（ticket 也只发给持 token 的调用方）。只接受 GET/HEAD，其余方法返回 405（明确拒绝 WebDAV 类动词）。

端点返回说明
GET /api/v1/healthJSON免认证探活，只回 {ok, service, version}
GET /api/v1/rootsJSON已发布根列表（名字、真实路径、条目数）
GET /api/v1/tree?root=&path=JSON目录列表：名称、类型（dir/text/image/other）、大小、修改时间。隐藏项与不支持的类型不会出现在列表里
GET /api/v1/meta?root=&path=JSON单文件元信息（类型、大小、修改时间）
GET /api/v1/raw?root=&path=原始字节文件内容。文本统一以 text/plain 返回，图片按 image/*，PDF 按 application/pdf。用户内容永远不会以 text/html 返回——渲染只发生在前端清洗之后
GET /api/v1/html-ticket?root=&path=JSON为 HTML 完整模式签发一次性 ticket（30 秒过期）
GET /api/v1/rawhtml?root=&path=&ticket=text/html完整模式唯一返回 HTML 的通道，凭证为一次性 ticket（不是 Bearer）。响应头强制 Content-Security-Policy: sandbox …（不含 allow-same-origin），文档获得不透明源：脚本可运行，但拿不到 viewer 的 token、localStorage 或任何同源数据

所有响应都带 X-Content-Type-Options: nosniff；API 响应额外带 Cache-Control: no-store。不设置任何 CORS 头，其他站点的页面无法读取响应。

六、渲染管线

类型管线
Markdown（.md/.markdown）marked 解析 → DOMPurify 清洗 → 注入容器 → highlight.js 高亮代码块。站内相对链接改写为查看器路由，外链加 rel="noopener noreferrer"；相对图片经认证接口取回后用 blob URL 展示
HTML（.html/.htm）默认模式DOMPurify 整文档清洗（保留样式与结构，剥离脚本与事件属性）后渲染；文档自带的站内相对样式表经认证接口取回后内联。覆盖绝大多数文档阅读场景
HTML 完整模式（按需切换）签发 ticket → 沙箱 iframe 加载 rawhtml。文档脚本可运行（交互式图表等），但处于不透明源沙箱，无法触及 token 与页面数据
纯文本 / 代码highlight.js 高亮展示（text/plain 原文永不执行）
图片 / PDFblob URL 直接展示；SVG 按图片渲染（<img> 上下文不执行脚本）

七、安全模型（威胁 → 对策）

威胁对策
陌生人访问文档（R4）Bearer token 必需；服务端存哈希、常数时间比较；认证失败按来源 IP 限速（15 分钟内 10 次失败即封禁一段时间）；token 可随时 rotate 吊销
借隧道读到未授权目录（R1）默认零发布；发布清单持久化且可即时撤销；每次请求做 realpath 包含性检查；指向发布根之外的符号链接拒绝；隐藏文件/目录（.git、.env…）默认跳过；扩展名白名单之外的文件不提供
恶意文档脚本偷 token / 冒充页面服务端对用户内容永不返回 text/html（渲染前一律 text/plain + nosniff）；前端 DOMPurify 清洗；完整模式走无 allow-same-origin 的 CSP sandbox iframe；viewer 自身配严格 CSP：default-src 'none'; script-src 'self'; frame-src 'self' blob:; base-uri 'none'; form-action 'none'（内容里的脚本、事件属性即使漏网也无法执行）
任何写入尝试（R2）代码里不存在写入端点；方法白名单 GET/HEAD，WebDAV 动词一律 405；不读取请求体
token 泄漏进日志/URLtoken 只走 Authorization 头；ticket 短寿命（30 秒）单次使用且绑定文件路径；审计日志只记事件与路径，永不记凭证
抵赖 / 事后追查JSONL 审计日志记录认证失败、发布变更、文件访问（时间、来源 IP、根、路径）
资源消耗（大文件拖垮手机/服务）渲染体积上限（默认 2 MB，超出时提示并允许强制渲染）；HTTP 线程设超时；拒绝超长 URL 与请求体
波及 agent 控制通道（R5）独立进程、独立端口、独立子域名、独立 token；绑定 127.0.0.1 只经隧道暴露；herdr-remote relay 零改动

残余风险：① 发布目录内非隐藏的敏感文件（比如 notes.yaml 里手写的密码）对持 token 者可见——发布前自行确认目录内容，或加 --docs-only 只放行文档类型；② 完整模式下文档脚本可运行，浏览器沙箱挡住了同源访问，但它仍可能发起网络请求（外联），不信任的 HTML 请用默认模式；③ token 一旦在手机上泄漏，等同于文档全集泄漏，发现后立即 token rotate。

八、验收标准

需求验收方式
R1 明确授权测试：未发布的目录在 tree/roots 不可见、文件接口 404；unpublish 后立即不可见
R2 只读测试：POST/PUT/DELETE/MKCOL/PROPFIND 等全部 405；代码无写入端点
R3 渲染测试 + 实测：md 渲染出标题/代码高亮，HTML 清洗后渲染，完整模式沙箱生效
R4 token测试：无 token 401、错 token 401、连续失败触发 429；实测手机端输入 token 后可浏览
R5 安全不碍事测试：响应头（nosniff/CSP）断言；herdr-remote 配置零改动（只新增 ingress 规则）
